# 01 — Foundation, tooling and deployment

## What this delivers

A running Next.js application, wired to Supabase, deploying to Vercel from
GitHub, with a working local development loop.

## Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 16 (App Router) + React 19 |
| Language | TypeScript, strict |
| Styling | Tailwind CSS 4 |
| Database / auth | Supabase (free tier, Mumbai region) |
| Hosting | Vercel |
| Node | 20.19.6, pinned in `.nvmrc` |

## Layout

```
src/app/           routes (App Router)
src/components/    shared UI primitives
src/lib/           supabase clients, domain logic
scripts/           dev wrapper, data build + test scripts
supabase/          config.toml and migrations
context/           these files
```

## Decisions and why

### Next.js 16 renamed `middleware` to `proxy`

`src/middleware.ts` is deprecated. The session-refresh and route-guard logic
lives in **`src/proxy.ts`**, exporting a function named `proxy`. The helper it
calls is `src/lib/supabase/session.ts`.

`AGENTS.md` in the repo root (generated by `next dev`) instructs that the
bundled docs under `node_modules/next/dist/docs/` be read before writing code,
because Next 16 has breaking changes. That is worth honouring — the `proxy`
rename and the fully-async request APIs (`cookies()`, `searchParams`, `params`
must all be awaited) were both found that way.

### The dev server must not be started with plain `npm run dev`

Use **`npm run dev:nvm`**, which runs `scripts/dev.sh`.

The machine's `nvm` default is Node 14, which cannot run Next 16. It is not
enough for the parent process to be on Node 20: Turbopack spawns child
processes for PostCSS and loaders that resolve `node` from `PATH`, so `PATH`
itself has to point at the right version. The symptom when it does not is a
misleading Turbopack panic — `TypeError: path.relative(...).replaceAll is not a
function` — because `String.prototype.replaceAll` did not exist until Node 15.

`scripts/dev.sh` sources `nvm`, runs `nvm use` (which reads `.nvmrc`), and then
execs `next dev`. The global nvm default was deliberately left alone, since
other projects on the machine may depend on it.

The browser-preview launch config in `../.claude/launch.json` (workspace root,
not this repo) points at `scripts/dev.sh` for the same reason.

### Git commit identity blocks Vercel builds

This cost a long debugging detour and is worth knowing about.

The machine's global git identity was `DXY <dkkrhwwyt@gmail.com>`, unrelated to
the GitHub or Vercel account. **Vercel's free plan refuses to build a commit
whose author is not a recognised account member, and it fails silently**: six
deployments were created and sat in `UNKNOWN` state with no duration and no
build logs. Nothing in the CLI, the deployment inspector or the logs endpoint
mentioned authorship.

Fixed by setting the global identity to `Dhananjay Rawat
<dhananjay.rtr@gmail.com>` and rewriting the existing commits' authorship
(verified content-identical by comparing tree hashes before force-pushing; a
local `backup-wrong-author` branch still points at the original history).

**If a deployment is accepted but never builds and produces no logs, check
commit authorship before investigating the build pipeline.**

### Environment variables

`.env.local` (git-ignored) and `.env.example` hold:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — the publishable key (`sb_publishable_…`)

Both are publishable: they ship to the browser and are governed by RLS. The
service-role/secret key is **not used anywhere** in the app and must never
reach the client.

Note `vercel link` appends `VERCEL_OIDC_TOKEN` to `.env.local`. That is
expected; `.env*` and `.vercel` are both git-ignored.

## Known gaps

- Supabase free tier pauses a project after ~7 days of inactivity and caps at
  500 MB. Fine for now; needs a paid plan before real users.
- The Vercel project's Node version is set to 24.x while local is 20.19.6.
  Builds pass, but the two are not identical.
- `abhyas.vercel.app` is **not** this project — it belongs to someone else. The
  production alias is `abhyas-indol.vercel.app`.
